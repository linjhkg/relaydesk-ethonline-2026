比较：
- A：深化活动交接；单一清楚问题，可以复用钱包安全和注册流程，把重点放在可验证权限范围。选择此项。

- C：彻底重选；剩余时间和单人执行带来交付风险，没有确定的更优候选，不选。**不是断言重选“没有胜算”。**

## 必须做到的差异化验收（尚未全部完成）

1. 两个活动名字 A/B，各自使用不同 Resolver 实例；同一志愿者。
2. A 授予 url-key 权限：志愿者可以修改 A，不能修改 B，也不能写其他字段。
3. 撤销 A：同一志愿者再写 A 被精确的链上权限错误拒绝；A 的原 URL 保留。
4. 每一步用本届 Universal Resolver 公众回读、root/key 位图、交易与回执支撑。
5. 界面和材料说明：权限覆盖整个 Resolver。独立实例是我们的部署纪律，不能证明没有其他名称指向同一实例，不能宣称全球按名称隔离。

不做：复制其他参赛者 agent heartbeat/fleet 方案、HCA/自动会话、多志愿者后台、为凑赛道增加未验证赞助方。
